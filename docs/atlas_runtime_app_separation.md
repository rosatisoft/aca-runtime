\# Atlas / Runtime / Application Separation



\## Principle



The Atlas measures.

The Runtime interprets.

The Application decides.



\## ACA Atlas



Produces geometric criterion signals:



\- semantic field

\- origin cost

\- epistemic orientation

\- trajectory continuity

\- preservation

\- drift

\- reorientation

\- inversion



The Atlas does not block, allow, select, or answer.



\## ACA Runtime



Interprets Atlas signals into operational states:



\- ALLOW

\- CLARIFY

\- REANCHOR

\- DECLARED\_SHIFT

\- RECOVERING

\- FLAG\_DRIFT



The Runtime does not decide the product behavior by itself.



\## Application Layer



Consumes Runtime signals according to use case.



Examples:



\- firewall: allow / block / flag

\- moderator: warn / clarify / reanchor

\- project assistant: preserve objective

\- candidate competition: rank / report

\- auditor: review / document risk



\## Design Rule



Do not confuse measurement with decision.



A signal is not an action.



Applications define actions.
